# 周排菜独立页面

## 功能是什么

点菜页的「饮食计划」原来是**绝对定位覆盖层**（`<plan-week>` 直接铺在点菜页上），点里面的「‹ 返回」或者按系统返回键，页面没反应，出不去。现在改成**独立页面** `pages/plan/index`，走页面栈的 `navigateTo` / `navigateBack`，返回键和页内返回都生效。

## 根因

1. 覆盖层不是页面，**不在页面栈里**，系统返回键没有可出栈的目标，所以「点了没反应」。
2. 覆盖层用 `position: absolute; inset: 0`，顶部落在自定义导航栏 / 状态栏区域，被原页面的 header 盖住，左侧返回按钮的点击被吞掉。

## 规则与边界

- 周排菜仍是「周一至周日 × 早餐/午餐/晚餐」，夜宵不排（`PLAN_MEALS`）。
- 一个家庭里「日期 + 餐次」只保留一份 `status: 'planned'` 文档。
- 从周排菜点 🛒 回购物车：不是 `navigateBack` + 事件，而是给 cart store 打一个一次性标记 `openCartOnBack`，回到点菜页的 `onShow` 消费掉再自动弹出购物车，避免跨页面传事件。

## 数据结构

无变更，仍存在 `order` 集合：

```js
{
  date: '2026-11-03',
  mealType: 'dinner',
  items: [{ dishId, name, cover, categoryId, count }],
  totalCount,
  note,
  status: 'planned',
  creatorOpenid,
  creatorName,
  familyId,      // 本次新增，见《用户角色与家庭》
  createTime,
  updateTime
}
```

## 接口

`order` 云函数不变：

| action | 说明 |
| --- | --- |
| `planSave` | 保存某餐排菜，`items` 为空视作清空该餐 |
| `planMove` | 整餐挪到别的日期/餐次，目标已有计划则合并 |
| `planClear` | 删除某餐计划 |

`findPlan()` 本次按家庭隔离，并补了权限校验（见《用户角色与家庭》）。

## 前端交互

| 位置 | 改动 |
| --- | --- |
| `pages/order/index` | `openPlan()` 改成 `uni.navigateTo({ url: '/pages/plan/index?start=...' })`；删掉 `weekMode` / `weekStartDate` / `onPlanCart` 与 `<plan-week>` 模板块；`onShow` 里消费 `cart.openCartOnBack` |
| `pages/plan/index` | 新页面：透传 `start` 给 `<plan-week>`；`@close` 走 `navigateBack`（失败则 `switchTab` 回点菜页）；`@cart` 打标记后 `switchTab` 回点菜页 |
| `pages.json` | 注册 `pages/plan/index`，标题「周排菜」 |
| `store/cart.js` | state 加 `openCartOnBack: false` |

## 兼容与迁移

页面路由变了，旧分享链接里没有 `/pages/plan/index`（以前根本没有这个路由），无需兼容。

## 验证清单

1. 点菜页点「饮食计划」→ 进入周排菜页。
2. 点页内「‹ 返回」→ 回到点菜页，购物车、菜列表状态正常。
3. 按系统返回键（安卓返回 / iOS 侧滑）→ 同样回到点菜页。
4. 在周排菜里点购物车图标 → 回到点菜页并自动弹出购物车，且只弹一次（再切 tab 回来不再弹）。
5. 周排菜里排一道菜 → 返回点菜页 → 食记页「排菜计划」页签能看到。
