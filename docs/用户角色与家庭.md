# 用户角色与家庭

## 功能是什么

把原来「一个家庭、admin/member 两种身份」的模型，升级成**三级平台角色 + 家庭归属**：

| 角色 | 标识 | 能看到什么 | 能建家庭 | 能管成员 |
| --- | --- | --- | --- | --- |
| 超级VIP | `supervip` | 所有家庭的菜品 / 分类 / 食记（在「浏览其他家庭的菜单」里切换），可把别家的菜**复制**到自己菜单；点菜页默认仍只看自己家庭 | 能 | 自己家庭的 |
| 普通VIP | `vip` | 本家庭成员创建的菜品 / 分类 / 食记 | 能 | 自己家庭的（仅房主） |
| 普通用户 | `user` | 只有自己创建的菜品 / 分类 / 食记 | **不能** | 否 |

配套能力：

- **一个账号只能在一个家庭**（`user.familyId` 唯一归属）。
- **创建家庭的即房主**，可以改名、发邀请、移除成员、解散家庭。
- **邀请即加入**：房主分享卡片 → 对方点开就进这个家，加入后 `user` 自动升级为 `vip`。
- **超级VIP 跨家导入**：浏览别家菜单 → 点「导入」→ 在**自己**名下生成一份新菜品（图片复用原 `fileID`，不重复占存储）。

## 规则与边界

- 角色不存在审批流程，**改角色只能进云开发控制台 → 数据库 → `user` 集合手动改 `role`**。
- 家庭名最长 20 字；成员上限 50（查询上限，足够家用）。
- 房主不能「退出家庭」，只能「解散家庭」；解散后所有成员 `familyId` 清空，菜品**不删除**，各自只看回自己创建的。
- 修改/删除权限：本人创建的菜自己可改；房主可管本家庭所有菜（含升级前无 `familyId` 的历史菜）；超级VIP 全场可管。
- 「加入家庭」不校验邀请有效期 —— 邀请靠分享卡片传参，拿到 `familyId` 即可加入；要收紧可后续加邀请码表。

### 可见范围（服务端统一实现）

```
supervip + allFamilies  → 不加条件（跨家浏览页的「全部」页签）
supervip + familyId     → familyId = 指定家庭（跨家浏览页选中某个家庭）
supervip 默认（有家庭）  → familyId = 我的家庭 + 历史无 familyId 数据
supervip 默认（无家庭）  → 不加条件
vip 且有 familyId       → familyId = 我的家庭 + 历史无 familyId 数据
user / 无 familyId      → creatorOpenid = 我
```

> 超级VIP 默认不跨家，是为了避免「点菜页把所有家庭的菜混在一起」。跨家浏览必须显式传参。

订单额外兜一层：`vip` 看到的历史订单（无 `familyId`）要求 `creatorOpenid` 属于**本家庭成员**，避免别人的旧单混进来。

## 数据结构

### `user`（记录主键即 openid）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | openid |
| `role` | string | `supervip` / `vip` / `user` |
| `familyId` | string | 所属家庭，空字符串表示没有家庭 |
| `familyRole` | string | `owner` / `member` |
| `inviterOpenid` | string | 被谁邀请进来的 |
| `nickName` / `avatar` | string | 资料 |

新用户默认 `role: 'user'`、`familyId: ''`。

### `family`（新增集合）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | 家庭 ID，被 `user.familyId` 引用 |
| `name` | string | 家庭名，默认「xx的小厨房」 |
| `ownerOpenid` | string | 房主 |
| `createTime` / `updateTime` | number | 时间戳 |

### `dish` / `category`

新增 `familyId`（创建者当时的家庭）与 `creatorOpenid`（菜品已有）。分类的 `creatorOpenid` 本次补齐。

### `order`

新增 `familyId`，下单 / 排菜计划都写入当时的家庭。

## 接口

### `user`

| action | 说明 |
| --- | --- |
| `me` | 返回用户 + `familyName` / `isOwner` / `memberTotal`，兼容历史 admin/member |
| `members` | 本家庭成员列表 |
| `bind` | 老邀请卡片兜底：按邀请人找到他的家庭后加入 |
| `removeMember` | 房主移除成员（只清 `familyId`，不删用户） |

`me` 在家庭文档缺失时**自愈**：按最早加入的成员补建 `family` 记录，老数据不用手动迁移。

### `family`（新增云函数）

| action | 权限 | 说明 |
| --- | --- | --- |
| `create` | `vip` 及以上，且当前无家庭 | 建家庭并把自己设为 `owner` |
| `info` | 登录用户 | 家庭信息 + 成员列表 + `isOwner` + 菜品数 |
| `join` | 登录用户，且当前无家庭 | 通过 `familyId` 加入；`role === 'user'` 时升为 `vip` |
| `leave` | 成员（非房主） | 退出家庭 |
| `removeMember` | 房主 | 移除成员 |
| `rename` | 房主 | 改家庭名 |
| `dissolve` | 房主 | 清空所有成员归属并删除家庭文档 |
| `list` | 仅 `supervip` | 所有家庭 + 人数 + 菜品数 + `isMine` |

### `dish`

- `list` 支持 `familyId`（看指定家庭）与 `allFamilies: true`（看全部家庭），两个参数只对 `supervip` 生效，用于跨家浏览页。
- 新增 `import`：仅 `supervip`，按 `_id` 复制一份到自己菜单。
  - 复制字段：名称、封面、图片、简介、食材、步骤、标签；`categoryId` 置空（跨家庭分类无意义）、`originDishId` 记来源。
  - 图片复用原 `cloud://` fileID，不产生新文件。

### `category` / `order` / `rank` / `stats`

同一套可见范围：列表、详情、写操作都按角色过滤；`rank.hot`、`stats.overview`、`stats.shoppingList` 只统计当前用户看得到的数据，避免热度榜 / 统计把别家菜品漏出来。

`order.cancel` 的「管理员」判断从 `role === 'admin'` 改为 `familyRole === 'owner'` 或家庭 `ownerOpenid`。

## 前端交互

### 「我」页（`pages/mine/index`）

- 头像旁标签：`超级VIP` / `家庭房主` / `家庭VIP` / `普通用户`。
- 副标题：有家庭显示「家庭名 · N 位家人」，没家庭提示去「我的家庭」。
- 「家庭与成员」卡片：家庭名 + 邀请按钮 + 成员列表（房主/成员）+「管理 ›」。
- 功能列表新增「我的家庭」，`supervip` 额外显示「浏览其他家庭的菜单」。

### 家庭管理页（`pages/family/index`）

- 没家庭：`vip` 及以上看到创建表单；`user` 看到「普通用户不能创建家庭，等邀请」。
- 有家庭：家庭名（房主可改名）、成员列表（房主可移除）、邀请按钮、退出 / 解散。
- 页面 `onShareAppMessage` 带 `familyId` 与 `inviter`。

### 跨家浏览页（`pages/family/browse`）

- 顶部横向滚动的家庭标签（含「全部」），选中后按 `familyId` 拉菜品。
- 每行「导入」→ 调 `dish.import` → 按钮变「已导入」。

### 邀请落地（`pages/order/index` 的 `onLoad`）

- 链接带 `familyId` → `family.join({ familyId, inviterOpenid })`，成功提示「已加入家庭小厨房」。
- 只带 `inviter`（老卡片 / 老小程序码）→ 走 `user.bind` 兜底。
- 小程序码 `scene` 形如 `familyId=xxx&inviter=yyy`，`readParam()` 两种入口都解析。

## 兼容与迁移

- 历史 `role: 'admin'` / `'member'` 在读的时候统一归一化成 `vip`，`admin` 视为 `familyRole: 'owner'`。
- 历史菜/分类没有 `familyId`：`vip` 的可见范围里显式带上「`familyId` 为空」的分支，不会凭空消失；房主可管理。
- 历史订单没有 `familyId`：按「创建人是否本家庭成员」判断可见性。
- 家庭文档缺失（只有 `user.familyId` 没有 `family` 文档）：`user.me` / `family.info` 会用最早加入的成员自动补建。

## 验证清单

1. 云开发控制台把测试号 `role` 改成 `supervip`，重进小程序 →「我」页标签显示超级VIP。
2. 普通用户进「我的家庭」→ 只能看到「不能创建家庭」提示，点菜页只有自己上传的菜。
3. 普通VIP 创建家庭 → 分享卡片给另一个号（`role: 'user'`）→ 对方点开提示「已加入家庭小厨房」，且 `role` 变成 `vip`。
4. 房主在「我的家庭」移除该成员 → 对方再进点菜页只看回自己的菜。
5. 超级VIP 进「浏览其他家庭的菜单」→ 切家庭 → 导入一道菜 → 自己菜单里出现副本，图片正常显示。
6. 「我」页统计数字与家庭范围一致；热度排行不再出现别家菜品。
7. 非房主 VIP 打开别人的菜品详情能看，但没有编辑/删除权限（服务端返回 `1003`）。
