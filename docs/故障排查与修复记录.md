# 故障排查与修复记录

按时间倒序记录线上/真机上出现过的故障：现象 → 根因 → 修复 → 验证，最新一条在最上面。

## 2026-11-03 点击分类后右侧菜品没有立即更新

**现象**

点菜页左侧点另一个分类，左侧高亮已经变了，但右侧列表看上去“没反应”：要么还停在原来的滚动位置（菜少的分类干脆是一片空白），要么搜索框里还留着上一个关键词。

**根因**

1. 右侧是 `scroll-view`，**换数据不会自动回到顶部**。切到菜少的分类时，旧的 `scrollTop` 超过新内容高度，看到的就是空白。
2. `menu.setCurrent()` 只清了 store 里的 `keyword`，页面上的 `searchInput` 没同步，搜索框仍显示旧关键词，视觉上与列表不一致。
3. 新分类还没请求过时，`currentBucket` 返回的是空 bucket（`loading: false`），页面无法区分「真的没菜」和「还没加载」。

**修复**

1. `src/store/menu.js` 新增 `pendingBucket()`（`loading: true`）：当前分类还没有 bucket 时拿它当占位，右侧直接进入「正在端上来…」，不再先闪空态。
2. `src/pages/order/index.vue`：右侧 `scroll-view` 加 `:scroll-into-view="scrollAnchor"`，列表首行 `dishes__head` 加 `id="dish-top"`；`selectCat` 里调 `scrollToTop()` 把列表滚回顶部（`scroll-into-view` 同一个值不会重复触发，要先清空再 `$nextTick` 设回）。
3. `selectCat` 同时清空 `searchInput`；`onSearch` / `clearSearch` 也调 `scrollToTop()`，搜索命中后不会停在旧位置。

**验证**

1. 连续快速点几个分类：右侧立即清空并显示「正在端上来…」，随后出现新分类的菜，不会停在上一个分类的滚动位置。
2. 在一个菜多的分类往下滚一段，再切到菜少的分类：列表在顶部，不会出现空白。
3. 搜索关键词后点分类：搜索框自动清空，列表回到顶部。
4. 点「清空」结束搜索：列表回到顶部。

## 2026-11-03 云函数改完上传后仍报旧错误

**现象**

本地已经修好云函数，重新上传并部署，线上还是报一模一样的错（例如 `docId必须为字符串或数字`）。

**根因**

`cloudfunctionRoot` 指向的是**编译产物**里的副本，不是根目录源码：

```
dist/dev/mp-weixin/cloudfunctions/     ← 开发者工具真正上传的
cloudfunctions/                        ← 我改的是这里
```

`scripts/sync-cloud.js` 只在 `build:mp-weixin` / `sync:cloud` 时把源码拷进产物。只改源码不同步，工具里右键上传的还是旧代码。

**修复**

改完云函数先 `npm run sync:cloud`（或 `npm run build:mp-weixin`，构建脚本内置同步）再上传；确认方法：产物里搜 `getWXContext` 能看到新代码。

**验证**

1. `dist/dev|build/mp-weixin/cloudfunctions/<名字>/index.js` 是刚改的内容。
2. 云开发控制台日志里 `[函数名:action]` 不再出现旧异常。

## 2026-11-03 点菜页分类全空，提示「docId必须为字符串或数字」

**现象**

进入点菜页，左侧分类栏是空的，页面显示「还没有任何分类 / 点右上角添加菜品」，同时弹出一个英文风提示：`docId必须为字符串或数字`。菜品、订单、统计等其它页面也可能连带空白。

**根因**

`category` 云函数在做可见范围改造时，`exports.main` 里漏掉了取用户身份这一行：

```js
// 问题代码
exports.main = async (event = {}) => {
  const { action, data = {} } = event
  const handler = ACTIONS[action]
  const result = await handler(data)   // ← 少了 openid
```

于是 `actionList` 里 `loadUser(undefined)` 执行 `db.collection('user').doc(undefined).get()`。
云开发数据库的 `.doc()` 只接受**非空字符串或数字**，传入 `undefined` 就抛出这句 `docId必须为字符串或数字`；异常被 `catch` 兜住后原样回传前端，分类列表接口整体失败 → 页面拿不到分类 → 空态 + 报错提示同时出现。

**修复**

1. `category` 云函数补齐身份：

```js
exports.main = async (event = {}) => {
  const { action, data = {} } = event
  const { OPENID } = cloud.getWXContext()
  const handler = ACTIONS[action]
  const result = await handler(data, OPENID)
```

2. 给 `category` / `dish` / `order` / `family` / `rank` / `stats` 的 `loadUser` 都加上守卫，避免以后同类漏传又把 SDK 报错透给用户：

```js
async function loadUser(openid) {
  // 少传 openid 时 .doc() 只会抛「docId必须为字符串或数字」，这里给出可读的提示
  if (!openid) throw new Error('未获取到用户身份，请重新进入小程序')
  const res = await db.collection(USER).doc(openid).get().catch(() => null)
  ...
}
```

**排查技巧**

- 看到 `docId必须为字符串或数字`，先怀疑 `.doc(x)` 的 `x` 是 `undefined` / `''`，而不是数据库权限或集合不存在。
- 云函数里凡是发现「整个列表突然空了 + 一条 SDK 原始报错」，优先检查 `exports.main` 有没有把 `OPENID` 传给 handler；`ACTIONS` 里每个 action 都靠这个参数做用户/家庭判断。
- 集合不存在报的是 `-502005 collection not exists`，权限不足报的是 `permission denied`，与本次的 `docId` 报错是三类不同问题，不要混。

**验证**

1. 重新上传 `category` 云函数（顺带 `dish` / `order` / `family` / `rank` / `stats`）。
2. 回到点菜页下拉/切换分类，分类栏恢复、无报错提示。
3. 云开发控制台 → 云函数日志，搜索 `[category:list]`，确认无 `docId` 异常。
4. 老账号（升级前创建的分类/菜品）能正常看到自己原来的菜单。
